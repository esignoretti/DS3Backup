# Phase 2.5 Plan 01: Multi-Schedule Support Summary

**One-liner:** Converted the scheduler from single-cron-expression-per-job to multi-schedule-per-job with full backward compatibility — BackupJob.CronExprs []string replaces CronExpr string across the entire scheduler stack, API, and CLI.

## Objective

Allow users to define multiple schedules per job (e.g., hourly incremental + daily full) by specifying multiple cron expressions. This is a foundational model change that subsequent resilience features build on.

## Key Changes

### Model Layer (`pkg/models/models.go`)
- `CronExpr string` → `CronExprs []string` on `BackupJob`
- Custom `UnmarshalJSON` migrates legacy single `cronExpr` configs to new format
- Backward-compatible JSON deserialization from existing config files

### Scheduler (`internal/scheduler/scheduler.go`, `job.go`)
- `Scheduler.entries` changed from `map[string]cron.EntryID` to `map[string][]cron.EntryID` (multi-entry per job)
- `ScheduleJob` now accepts `[]string`, validates each expression, rollbacks partial schedules on failure
- `UnscheduleJob` removes ALL entries for a job (mitigates T-2.5-03)
- `ReloadJobs` iterates each job's `CronExprs`, skips invalid expressions with warning (mitigates T-2.5-02)
- `JobSchedule` struct updated: `CronExprs []string` replaces `CronExpr string`
- `EnableJobSchedule` / `RescheduleJob` accept `[]string`

### API (`internal/api/types.go`, `handlers.go`)
- `BackupJobWithStatus.CronExprs` replaces `CronExpr` in API responses
- `CreateJobRequest` supports both `cronExprs` (preferred) and `cronExpr` (deprecated, single-string fallback)
- `handlePatchJob` accepts `cronExprs` array with `cronExpr` backward compat
- `sanitizeJob` computes nearest `NextRun` across ALL cron expressions
- `JobManager` interface: `CreateJob` signature updated to `[]string`

### Daemon Adapter (`internal/cli/daemon.go`)
- `CreateJob` updated to accept `[]string`, uses `CronExprs` field

### CLI (`internal/cli/job.go`)
- Job list displays `CronExprs` instead of `CronExpr`
- Job schedule commands use `CronExprs` internally
