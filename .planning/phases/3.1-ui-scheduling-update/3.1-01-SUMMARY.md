# Phase 3.1 Plan 01: API Retry & Interval Fields Summary

**Exposed retry count, next retry time, and @every interval expression support through the REST API for dashboard consumption**

## Key Changes

### Model Layer (`internal/api/types.go`)
- Added `RetryCount int` and `NextRetryTime time.Time` fields to `BackupJobWithStatus` (both `omitempty`)
- `sanitizeJob` now uses a **dual cron parser** approach:
  - `standardParser` — 5-field cron (`cron.Minute | cron.Hour | cron.Dom | cron.Month | cron.Dow`)
  - `enhancedParser` — same 5 fields + `cron.Descriptor` for `@every`, `@daily`, `@hourly`, etc.
  - Each expression is tried against `standardParser` first, falls back to `enhancedParser`
  - Populates `RetryCount` and `NextRetryTime` from the job model

### API Handlers (`internal/api/handlers.go`)
- Removed unused `robfig/cron` import (already imported via types.go)

### Tests (`internal/api/api_test.go`)
- `TestBackupJobWithStatus_RetryFields` — verifies retry fields appear in JSON for jobs with retries, omitted for clean jobs
- `TestSanitizeJob_IntervalExpressions` — verifies `@every 6h` produces a valid future NextRun
- `TestSanitizeJob_MixedCronAndInterval` — verifies mixed `["0 2 * * *", "@every 12h"]` computes nearest NextRun
- `TestAPIResponseFormat_JobList` — now checks for `retryCount` and `nextRetryTime` fields (mock job updated with RetryCount=1)
