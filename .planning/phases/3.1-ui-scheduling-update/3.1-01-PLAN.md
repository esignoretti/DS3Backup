    a. Update the NextRun computation to handle `@every` expressions. The current code only uses `cron.NewParser(cron.Minute | cron.Hour | cron.Dom | cron.Month | cron.Dow)` which does NOT parse `@every`. Add a second parser with `cron.WithSeconds()` or better, use `cron.NewParser(cron.Minute | cron.Hour | cron.Dom | cron.Month | cron.Dow | cron.Descriptor)` — but `cron.Descriptor` is not a standard parser option in robfig/cron. Instead, upgrade to using `cron.NewParser(cron.Minute | cron.Hour | cron.Dom | cron.Month | cron.Dow)` as the primary and `cron.NewParser(cron.Minute | cron.Hour | cron.Dom | cron.Month | cron.Dow | cron.Descriptor)` as a fallback for each expression.

    Actually, the simplest approach: Try parsing each cron expression with the 5-field parser. If it fails, try parsing with `cron.NewParser(cron.Minute | cron.Hour | cron.Dom | cron.Month | cron.Dow | cron.Descriptor)` which supports `@every`, `@hourly`, `@daily`, etc. Store the appropriate parser in an `enhancedParser` var.

    ```go
    // Type to hold cron parser for runtime use
    var standardParser = cron.NewParser(cron.Minute | cron.Hour | cron.Dom | cron.Month | cron.Dow)
    var enhancedParser = cron.NewParser(cron.Minute | cron.Hour | cron.Dom | cron.Month | cron.Dow | cron.Descriptor)
    ```

    Then in the cron expression loop, try `standardParser.Parse(expr)` first, fall back to `enhancedParser.Parse(expr)`:

    ```go
    var nearest time.Time
    for _, expr := range job.CronExprs {
        sched, err := standardParser.Parse(expr)
        if err != nil {
            sched, err = enhancedParser.Parse(expr)
        }
        if err == nil {
            candidate := sched.Next(now)
            if nearest.IsZero() || candidate.Before(nearest) {
                nearest = candidate
            }
        }
    }
    ```
